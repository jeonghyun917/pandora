# 답변 보정 문맥 유실 진단

기준 커밋: `4d261c72`. 2026-09-29.

## 확인된 사실

- `OpenAiAnswerClient.rewrite`는 외부 API를 호출하지 않는다. 검증된 원자들을 줄바꿈으로 연결하는 결정적 구현이다. 프롬프트 조정으로 이번 문제를 해결할 수 없다.
- `ClaimEvidenceAtomizer.stripRepeatedOcrPageHeading`은 중복 OCR 페이지 제목을 제거한다. `GroundedAnswerRepairService`는 이 원자들을 선택한다.
- 저장된 security-review-target 답변은 세 가지 근거 있는 구축 항목을 담고 있지만, 국가정보원 검토 대상이라는 절 범위를 포함하지 않는다.
- 평가의 누락 명제는 일반 보안성검토 대상 표현이다. '국가정보원 검토 대상'만 복원하더라도 해당 oracle이 통과한다고 보장할 수 없다. 기관별 검토 대상과 전체 검토 대상을 동일시해서는 안 된다.

## 재현 및 기각한 실험

실제 검증기를 사용하는 재현 테스트를 작성했다. 중복 OCR 제목과 세 구축 항목을 담은 공식문서를 입력하고 결정적 rewriter를 사용했다.

1. 기존 구현: 답변은 생성되지만 원문 범위 제목이 빠져 테스트 실패.
2. 실험 구현: 직접 근거 본문 시작에 실제 존재하는 80자 이하 절 제목만 원자에 접두. 기존 검증/정렬 검사를 그대로 적용.
3. 결과: 답변 보정 테스트 55개 중 54개 통과, 새 테스트 실패. `NO_ALIGNED_SUPPORTED_ATOM`으로 거절됨. 제목과 항목을 붙이는 것만으로는 현재 검증기가 관계를 인정하지 않는다.

실험 코드와 테스트는 [기각된 패치](rejected-scope-heading-prototype-20260929.patch)에 보존했으며 실제 Java 소스에서는 제거했다. 이 패치는 해결책이 아니며 그대로 적용/배포하지 않는다.

## 안전 경계 및 다음 단계

- 외부 평가 호출/새 배포/authority 변경 없음. 기존 8080 JAR을 유지했다. 18080/output 변경 없음.
- 검증 기준이나 평가 정답을 완화하지 않았다.
- 다음 수정은 원문에서 제목이 지배하는 목록 범위를 명시적으로 표현하는 최소 설계가 필요하다. 제목이 바뀌면 범위 상속을 끊고, 서로 다른 기관/예외/대상을 섞지 않는 양성·음성 테스트가 먼저 필요하다.
- 제목의 단어를 답변 앞에 붙여 평가 문자열만 충족시키는 방식은 사용하지 않는다.
- 전체 1003개 게이트는 아직 실행하지 않는다. 마지막 검증된 live 결과는 3/4다.
- 이 실험으로 target/classes는 기준 소스와 다를 수 있으므로 다음 배포 전 반드시 다시 패키징한다. 현재 실행 JAR은 실험 코드가 아닌 이전 검증 JAR이다.
