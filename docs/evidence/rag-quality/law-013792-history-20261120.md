## Reference-qualified server path

The server implementation adds a separate, narrow request type: an explicit
reference date and one named law's general commencement date and general
effective status. The existing `isCurrentLookup` restriction remains intact;
the new request does not discard the year or infer past status from CURRENT.

`OfficialEffectivePhaseEvidence` reuses the existing complete, source-owned
commencement resolver and joins only the exact numeric official law/edition
history URL. It retains document/chunk/version ownership, the reference and
observation dates, the closed effective interval, and the fetched history hash.
The same full exception-bearing supplementary clause travels to generation.
Identical text in a different owner/edition/version cannot inherit this proof.

The public history reader uses HTTPS to the fixed law.go.kr endpoint, without
credentials, redirects or retries, with connect/read timeouts and a 200,000-byte
response cap. One attempt is shared across initial and fallback judging in a
retrieval. Unavailable, malformed or unbounded history fails closed. Reference
answers bypass the response cache to capture their own receipt. No source data,
Qdrant collection, evaluation contract registration or frozen oracle changes.

Final alignment requires exactly the separately supported official date and
reference-qualified general-status claims from that bound owner, with no
unsupported, contradicted or numeric-unsupported claims. All-provision status,
specific delayed provisions, another law and a different reference date do not
inherit that acceptance. A request for a different scope remains unsupported;
this is not a legal-status engine for arbitrary historical amendments.
